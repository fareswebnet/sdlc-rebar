# ReleasePilot Hermes Context

## Project

ReleasePilot helps small product-engineering teams transform feedback, support tickets, product signals, and production incidents into product decisions, verifiable specs, engineering tickets, PR evidence, release notes, and post-release learning.

## Current Feature

Build the first `Signal Clustering` vertical slice.

The slice groups similar feedback signals, proposes a priority with evidence, exposes confidence and conflicts, and lets a product owner accept, reject, or split a cluster before a spec is generated.

## Mandatory Engineering Process

Do not start implementation until these gates are satisfied:

1. Intent and non-goals are explicit.
2. Domain concepts and bounded contexts are mapped.
3. BDD scenarios are written and accepted.
4. Architecture and data ownership are approved.
5. Feature flag owner and rollout conditions are recorded.
6. Red tests exist for the accepted behavior.

Implementation must follow:

`red -> green -> refactor -> review -> release readiness -> production learning`

## Validation Commands

Use the commands already present in the target repo. If the repo has no equivalent command, record the gap instead of inventing success.

Expected command names for the example:

```bash
npm run lint
npm run typecheck
npm run test
npm run test:e2e -- signal-clustering
```

## Protected Areas

Do not modify these areas without explicit human approval:

- authentication and authorization
- tenant isolation
- billing or payments
- secrets, tokens, and environment files
- production deployment configuration
- destructive migrations
- customer communication templates
- third-party data-processing agreements

## Output Discipline

Each agent must write or update a durable artifact under `docs/`, `features/`, `tests/`, or the PR body. Conversational summaries are not enough.

Each handoff must include:

- decision
- rationale
- affected files
- validation evidence
- residual risk
- next owner

## Autonomy Boundary

Hermes may coordinate subagents, schedule checks, run safe validation commands, and prepare PR content. Hermes must not deploy, change secrets, contact customers, or approve its own gates.
