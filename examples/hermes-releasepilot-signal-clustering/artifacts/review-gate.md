# Review Gate - Signal Clustering

## Decision

Conditionally mergeable after human review, assuming the real implementation diff is scoped to the approved paths and the validation commands pass.

## Blocking Findings

None in the simulated artifact set.

## Required Evidence Before Merge

- BDD scenarios are committed and accepted.
- Domain tests fail before implementation and pass after implementation.
- Component tests cover empty, loading, low-confidence, accepted, rejected, and error states.
- Cross-tenant access test passes.
- Feature flag file documents owner, environments, enable conditions, and rollback.
- Security review confirms that feedback text is treated as sensitive data.
- PR body links behavior, architecture impact, tests, rollout, and residual risk.

## Review Checklist

| Area | Gate |
|---|---|
| Product | Scope is limited to Signal Clustering first slice. |
| Domain | Cluster, evidence, confidence, conflict, and validation invariants are explicit. |
| BDD | Examples cover ready, low-confidence, conflict, acceptance, and tenant isolation. |
| TDD | Tests were red before implementation. |
| Architecture | Clustering is isolated behind a domain service. |
| Data | Tenant ownership and audit events are clear. |
| Security | Prompt-like signal text cannot instruct the agent or app. |
| UX | Human validation is required before spec generation. |
| Release | Production remains behind a disabled flag. |
